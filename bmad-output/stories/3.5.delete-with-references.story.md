# 3.5: Deleting a block or signal removes the references to it

**Story ID:** 3.5  
**Epic:** 3 — Wiring and validation in the editor  
**Slug:** delete-with-references  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **deleting a block, signal or variable to also remove the wires pointing to it**,  
so that **the project never contains dangling references**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Removing a `BlockInstance`, `SignalInRef`, `SignalOutRef` or `Variable` (`cmdRemove`) also removes every `Source` whose `Ref` points to it or to one of its `Output`s, in the **same** undo step.
2. Undo restores the element and every removed `Source` in their original positions.
3. Renaming never touches references (they use `IUuid`, not titles).
4. A summary is logged at Info level ("Removed block X and 3 connections").

## Tasks / Subtasks

- [ ] Build the reference index lookup (`Ref` → Source nodes) (AC: #1)
- [ ] Extend `cmdRemove` into a macro (AC: #1, #2)
- [ ] Tests (AC: #1, #2, #3)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Deleting a node must also remove or clear the references to it (`Ref`, `Io`) inside the same macro, so undo restores everything. [Source: architecture.md#adr-002]
- References always point to `IUuid` values. [Source: architecture.md#adr-002]
- Channels referenced by `SignalRef/@Io` are handled the same way: deleting a channel in the tree removes or clears the `Io` of the signal refs (removing the SignalRef is preferred, so no wire is left broken). [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** unit tests.
- **Key scenarios:** delete a block with 2 incoming and 3 outgoing wires; undo.
- **Per-AC verification:** AC #1 → count the Sources before/after; AC #2 → undo → document identical to before (serialise and compare); AC #3 → rename → no Source changed; AC #4 → log spy
- **Fixtures / mocks:** a small page fixture.
- **Edge cases to cover:** a source wired to two inputs of the same block.
