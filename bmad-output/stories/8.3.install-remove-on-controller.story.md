# 8.3: Install and remove packages on the controller

**Story ID:** 8.3  
**Epic:** 8 — Controller libraries and dependency check  
**Slug:** install-remove-on-controller  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to install or remove a package on the controller from STIx Config**,  
so that **the controller has the libraries my project needs**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. "Install on controller" sends the package with chunked `InstallLibrary {uuid, vers, sha256, size}`, with progress; the result updates the catalogue.
2. "Remove from controller" sends `RemoveLibrary {uuid, vers}`; a refusal because the running project uses it is shown clearly.
3. Unsigned packages are refused by a controller not in developer mode; the message says so.
4. Admin role only.

## Tasks / Subtasks

- [ ] Install with progress (AC: #1)
- [ ] Remove (AC: #2)
- [ ] Signature/developer-mode errors (AC: #3)
- [ ] Role gating (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Packages travel Shop → Editor → Controller; the editor is the broker. [Source: architecture.md#adr-012]
- `InstallLibrary` (chunked, Admin), `RemoveLibrary` (refused if the running project uses it, Admin). [Source: architecture.md#6-1-stix-link-messages-protocol-v1]
- A controller installs only signed packages, except in a clearly flagged developer mode. [Source: architecture.md#adr-004] [Source: architecture.md#adr-008]
