# 2.5: `Project/@Rev` and per-controller `BaseRev`

**Story ID:** 2.5  
**Epic:** 2 — Project file format v1.0.0  
**Slug:** rev-and-baserev  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **STIx Config to know which controller revision my project is based on**,  
so that **an upload never silently overwrites changes made on the controller**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `Project/@Rev` is read on load and kept unchanged on save; a new project is created with `Rev="0"`. The editor never increments `Rev` (only the controller does).
2. `Project.info` exposes `rev` to QML.
3. A `SyncState_class` stores and returns `BaseRev` per (project folder, controller serial) in `<project>/.stix/sync.xml`; the folder is created on first use.
4. `.stix/` is documented as an editor cache that should not be versioned.
5. Unit tests cover reading and writing `Rev` and `BaseRev` and a missing `sync.xml`.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- `Project/@Rev` is the revision number, which the controller increments on every save; the project hash changes with it. [Source: architecture.md#adr-017] [Source: architecture.md#adr-003]
- STIx Config stores the `Rev` it last uploaded or downloaded (`BaseRev`); `UploadProject` carries `baseRev`, and the controller refuses with `RevConflict` if its Rev is newer. [Source: architecture.md#adr-017]
- Storage: project folders may contain `.stix/` (editor cache, not versioned). [Source: architecture.md#5-data-model]
- Keying `BaseRev` by controller serial allows the same project to be deployed to a test and a production controller. [Inference]
- `SyncState_class` lives in `src/Components/ProjectSync/` because Epic 9 builds `ProjectSync` on it. [Source: architecture.md#component-projectsync-l3-new]
