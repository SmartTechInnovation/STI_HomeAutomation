# 10.4: SourceIds, value slots, subscriber arrays and `bind()`

**Story ID:** 10.4  
**Epic:** 10 — STIx Runtime MVP (separate repository `stix-runtime`)  
**Slug:** subscriber-wiring  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the controller**,  
I want **every connection resolved once into arrays of direct callbacks**,  
so that **an event reaches its targets with no lookups at run time**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Every source (block output, input signal, variable) gets a `SourceId` (uint32) and a 16-byte value slot in one contiguous array; slot payloads are written with an atomic 64-bit store.
2. For each source, a contiguous subscriber array holds one `{instance, on_input, input_idx}` entry per `<Source>`, in `<Source>` order — covering fan-out, fan-in and two inputs of the same block.
3. `bind()` gives each instance the `SourceId`s connected to each of its inputs (`stix_bind_info`) before the first event.
4. A symbol table `IUuid(.port) → slot, type` is produced for monitoring.
5. All arrays are allocated at load; nothing is allocated afterwards.

## Tasks / Subtasks

- [ ] SourceId + slot allocation (AC: #1, #5)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Load and wire: give every source a numeric `SourceId` and a value slot; for every source build a contiguous **subscriber array** with one entry `{instance, on_input, input_idx}` per connection; `bind` gives each instance the SourceIds per input; build the tick schedule. [Source: architecture.md#adr-005]
- Slot type is fixed at load; only the 8-byte payload changes, stored with a single atomic 64-bit write; strings are immutable, ref-counted handles. [Source: architecture.md#adr-005]
- Subscriber order follows the `<Source>` elements (deterministic; blocks must not rely on it). [Source: architecture.md#adr-005]
- Symbol table `IUuid` → slot for monitoring. [Source: architecture.md#adr-005]
