# 5.2: Header-only C++ wrapper: `stix::Block` and `stix::Driver`

**Story ID:** 5.2  
**Epic:** 5 — Plugin SDK and C ABI  
**Slug:** cpp-wrapper  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **a block author writing C++**,  
I want **to derive from a small base class instead of filling a C function table**,  
so that **a simple block is a few lines of readable code**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `sdk/stix_cpp.hpp` provides `stix::Block` with virtual `onBind`, `onInput(input, from, value)`, `run(now)`, `onProperty(idx, value)` and helpers `emit(out, v)`, `emitIfChanged(out, v)`, `setProperty(idx, v)`, `log(level, text)`.
2. `stix::Driver` provides `open`, `close`, `write(channel, v)`, `emitSignal(channel, v)`, plus an optional `QueuedWriter` adapter that moves `write` calls to the driver's own thread.
3. A macro `STIX_DEFINE_PLUGIN(ClassName, "type-uuid", KIND)` generates the `stix_plugin_entry` table; no exception can escape into C (every trampoline catches all exceptions and logs them).
4. The wrapper adds no heap allocation to `onInput` / `emit` calls.
5. The And example from 5.4 compiles against it in under 40 lines.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- The SDK ships a header-only C++ wrapper (`stix::Block` with `onInput`, `run`, `emit`, `emitIfChanged`) so block authors don't write the C table by hand. [Source: architecture.md#adr-006]
- `write` must be thread-safe and non-blocking; the SDK provides a ready-made adapter that queues the value to the driver's own thread. [Source: architecture.md#adr-005]
- No heap allocation in callbacks or ticks. [Source: architecture.md#adr-005]
- Fan-in style: AND keeps a map of sources (prepared in `bind`); Lighting acts on the last event. [Source: architecture.md#6-2-plugin-c-abi-v1]
