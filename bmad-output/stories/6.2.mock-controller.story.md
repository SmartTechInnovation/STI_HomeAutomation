# 6.2: `stix-mock-controller`: a development Link server

**Story ID:** 6.2  
**Epic:** 6 — Controller connection (editor side)  
**Slug:** mock-controller  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the STIx Config developer**,  
I want **a local server that speaks the STIx Link like a controller**,  
so that **I can build and test every editor feature before the real runtime exists**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `tools/stix-mock-controller` is a Qt console app (TLS with a generated self-signed certificate) that implements `Hello`, `Auth` (accounts from a config file), `GetInfo`, `UploadProject` (stores the file, increments `Rev`, honours `baseRev` → `RevConflict`), `DownloadProject`, `GetBase`, `ActivatePrevious` and `State`.
2. It implements monitoring from a script: `GetSymbols` derived from the uploaded XML, `Subscribe`, synthetic `ValueBatch` (sine, toggle, counter), `Force`/`Release`, `SetVariable`, `SetParams` (updates its stored XML + `Rev`, pushes `ProjectChanged`).
3. It implements libraries: `ListLibraries`, `InstallLibrary`, `RemoveLibrary`, `CheckProject`, served from a folder.
4. Commands on stdin inject `Fault`, `Log` and `ProjectChanged` pushes and simulate an HMI edit.
5. It is built in CI and used by the integration tests of Epics 6–9.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- The Link message table is the spec; an echo test server exists for development. [Source: architecture.md#adr-007]
- Upload and Rev semantics: `UploadProject {sha256, baseRev, force}` → `RevConflict{rev}` if the controller's project changed since baseRev; the controller keeps Base (the last upload). [Source: architecture.md#adr-017]
- `ValueBatch` at most every 50 ms with only the changed slots. [Source: architecture.md#adr-007]
- Roles: Admin ⊃ Engineer ⊃ Viewer; HmiUser separate. [Source: architecture.md#6-1-stix-link-messages-protocol-v1]
- This removes the editor's dependency on Epic 10. It is test tooling, not a product; keep it simple, with no plugin loading. [Inference] [Source: epics.md#notes]
