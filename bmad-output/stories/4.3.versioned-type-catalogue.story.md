# 4.3: Types keyed by `(Uuid, Vers)` and resolved through `<Requires>`

**Story ID:** 4.3  
**Epic:** 4 — Library packages and catalogue (editor)  
**Slug:** versioned-type-catalogue  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **a project to use exactly the package versions it declares, even when newer ones are installed**,  
so that **a project behaves the same on every PC and controller**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `BlockManager` and `SchemaManager` (periphery types) load their types from `LibraryService`, keyed by `(Uuid, Vers)`.
2. When a project is open, each type is resolved through its `<Requires>` entry; new blocks placed from the menu use the newest installed version.
3. A project requiring a version that isn't installed opens normally; the affected instances are marked "missing package" and listed by the validator.
4. The 2.4 `PackageInfoProvider` is replaced by a LibraryService-based one that fills `Sha256`.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- `BlockManager` and `SchemaManager` load types from the library store, keyed by `(Uuid, Vers)`, not only by `Uuid`; a project resolves each type by its `Requires` entry. [Source: architecture.md#adr-004]
- Identity = `Uuid` + `Vers` + `Sha256`. [Source: architecture.md#adr-004]
- NFR-06: a project never runs against a different library build than the one it declares. [Source: architecture.md#0-requirements-baseline]
- The project schema (`templates/schema/Project_EN.xml`) is not a package and still loads as today. [Inference]
