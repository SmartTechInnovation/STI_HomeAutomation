# 2.2: `ConfigVers`, the migration chain, and read-only for newer files

**Story ID:** 2.2  
**Epic:** 2 — Project file format v1.0.0  
**Slug:** config-version-and-migrations  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **old projects to open in new versions of STIx Config and newer projects never to be damaged by an old one**,  
so that **my projects stay usable forever**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. A `SemVer_s` type parses and compares `MAJOR.MINOR.PATCH`; an invalid or missing `ConfigVers` is treated as `0.0.0`.
2. On load, if the file's MAJOR is lower than the editor's, the ordered migration chain (`Migration_N_to_N+1`, pure functions on the `XmlNode_class` tree) runs, and the project is marked modified.
3. Before the first save of a migrated file, the original is copied to `Project.xml.bak-<oldVersion>`; the saved file carries the current `ConfigVers`.
4. If the file's MAJOR is higher than supported, the project opens **read-only**: `cmd*` calls are refused with `ErrorCode_e::VersionTooNew`, Save is disabled, and a warning is shown.
5. The chain is a registry (`registerMigration(from, fn)`) that is empty for 1.0.0; a test registers a dummy 0→1 migration and checks that it runs exactly once and in order.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- `Project/@ConfigVers` is SemVer. MINOR/PATCH = additive only (older editors keep the unknown parts); MAJOR = structural, with an ordered migration chain where each migration is a pure function on the `XmlNode_class` tree and runs on load. [Source: architecture.md#adr-003]
- The editor always **writes** the current version and keeps `Project.xml.bak-<oldVersion>` before it first overwrites an older file; a newer MAJOR opens **read-only** with a clear warning. [Source: architecture.md#adr-003]
- Baseline: no format has been released yet, so `ConfigVers 1.0.0` frozen at the MVP release already includes `<Requires>` and several `<Source>` per `<Input>`. [Source: architecture.md#adr-003]
- Use `ErrorCode_e::VersionTooNew` and the log-once rule. [Source: architecture.md#adr-010]
- Migrations are L2 (Project); `SemVer_s` is a plain L1 utility. [Inference] [Source: architecture.md#2-architecture-pattern]
