# 6.6: `ControllerConnection.qml` bound to `ControllerLink`

**Story ID:** 6.6  
**Epic:** 6 — Controller connection (editor side)  
**Slug:** connection-ui  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **the connection panel to show the real connection state**,  
so that **I always know whether I'm connected, to which controller, and what went wrong**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `ControllerConnection.qml` drops its local `connectionState` and binds to `ControllerLink.state`; "Connect to controller" calls `ControllerLink.connectToController()` for the active project's `RootDevice`.
2. Connected state shows serial, model, runtime version, logged-in user and role, and a Disconnect button.
3. Errors show `ControllerLink.lastError` with a Retry action.
4. `programDifferent` is true when the controller's project hash differs from the local one (from `GetInfo`).

## Tasks / Subtasks

- [ ] Bindings and actions (AC: #1, #3)
- [ ] Connected-state content (AC: #2)
- [ ] Program-different indicator (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- `ControllerConnection.qml` loses its local `connectionState` and binds to `ControllerLink.state`. [Source: architecture.md#adr-009]
- `ControllerLink` exposes `state` (Disconnected, Connecting, Connected, Error), `controllerInfo`, `programDifferent` and `roles`. [Source: architecture.md#component-controllerlink-l3-new]
- The current file already has the visual states and the `programDifferent` / `debugEnabled` properties; reuse the layout and replace only the data sources. [Inference] (from ControllerConnection.qml)

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->
