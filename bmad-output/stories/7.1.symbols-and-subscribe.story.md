# 7.1: Symbol table and subscriptions for the visible page

**Story ID:** 7.1  
**Epic:** 7 — Live monitoring and force  
**Slug:** symbols-and-subscribe  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **the editor to subscribe only to the values I can see**,  
so that **monitoring stays fast on the controller and the network**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. After upload or connect, `GetSymbols` is requested; a `SymbolTable_class` maps `IUuid` (and `iUuid.port`) ↔ slot ↔ type, and is invalidated when the project hash changes.
2. When monitoring is on, the editor subscribes to the slots of the active page (ports, signals, variables) with `Subscribe {slots, periodMs: 50}`, and unsubscribes when the page changes.
3. A local project that differs from the controller's (hash mismatch) disables monitoring with a message ("upload or download first").
4. Monitoring can be toggled from the top bar; a Viewer role can monitor.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Monitoring: the client sends `Subscribe {slots:[…]}` using the indexes from the symbol table; the controller sends `ValueBatch` at most every 50 ms with only the changed slots. [Source: architecture.md#adr-007]
- The runtime produces a symbol table (`IUuid` → slot index) for monitoring. [Source: architecture.md#adr-005]
- `GetSymbols` → `{projectHash, symbols:[[iuuid, slot, type]]}`, role Viewer. [Source: architecture.md#6-1-stix-link-messages-protocol-v1]
- NFR-09: ≤ 100 ms change-to-screen; < 5 % controller CPU. [Source: architecture.md#0-requirements-baseline]
