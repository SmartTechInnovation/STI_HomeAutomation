# 1.5: Shared error codes and `bool` + `failed` signal on ProjectManager

**Story ID:** 1.5  
**Epic:** 1 — Foundation and conventions  
**Slug:** result-and-error-codes  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the STIx Config developer**,  
I want **one error enum and one way to report failures**,  
so that **callers and the Link protocol react to the same reasons and magic `int` returns disappear**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `src/Components/Errors/errors.h` (L1) defines `enum class ErrorCode_e` (at least `Ok, InvalidArgument, NotFound, IoError, ParseError, VersionTooNew, TypeMismatch, Unauthorized, Forbidden, RevConflict, NetworkError, TlsError, Timeout, Internal`) and `struct Result_s { ErrorCode_e Code; QString Message; bool ok() const; }`.
2. Every component has a `<MODULE>_NAME` define used as the logger module name (as `RESOURCE_URL_NAME` is today).
3. All `Q_INVOKABLE` methods of `ProjectManager_class` return `bool` instead of `int`, and failures also emit `failed(int code, QString message)`.
4. QML callers in `Main.qml` still work; nothing in QML depends on the old `int` values.
5. Each failure is logged once, where it is detected.

## Tasks / Subtasks

- [ ] Create `errors.h` with the enum, `Result_s` and a `toString(ErrorCode_e)` (AC: #1)
- [ ] Add missing `<MODULE>_NAME` defines (AC: #2)
- [ ] Change the ProjectManager signatures and add the `failed` signal (AC: #3, #5)
- [ ] Check `Main.qml` call sites (`newProject`, `saveProject`, `undoProject`, `redoProject`, …) (AC: #4)
- [ ] Unit tests (AC: #1, #3)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Decision: no exceptions across module or event-loop boundaries; fallible operations return `bool`, or `Result_s {ErrorCode_e; QString}` when the caller must react to the reason; `ErrorCode_e` is one shared L1 enum mirrored by the Link `Error` codes. [Source: architecture.md#adr-010]
- Log once where detected: `S_Logger.write(Log::Warning|Error, <MODULE>_NAME, text)`. Users see errors in `LogTab`, not modal dialogs, except data-loss prompts. [Source: architecture.md#adr-010]
- New `Q_INVOKABLE`s return `bool` or emit `failed(code, message)`, never magic `int`s; existing `int` returns are migrated in this cleanup story. [Source: architecture.md#adr-010]
- Naming: `ErrorCode_e` (enum suffix `_e`), `Result_s` (struct suffix `_s`), members `PascalCase` for public struct fields. [Source: architecture.md#adr-011]
- `RevConflict` is needed later by the upload flow (6.7, 9.3). [Source: architecture.md#adr-017]

- **Approach:** unit tests on errors.h and ProjectManager.
