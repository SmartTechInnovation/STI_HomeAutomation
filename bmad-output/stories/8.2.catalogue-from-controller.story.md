# 8.2: One catalogue: controller + local, with the source shown

**Story ID:** 8.2  
**Epic:** 8 — Controller libraries and dependency check  
**Slug:** catalogue-from-controller  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **the blocks menu and library manager to show controller and local packages together**,  
so that **I see what is installed where**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `LibraryService` merges repositories by `(Uuid, Vers)`; each row lists its sources (Controller, Local, Templates).
2. When connected, the blocks menu prefers controller versions; a type only available locally is marked "not on controller".
3. The library manager (4.6) shows the Source column and filters by source.
4. Disconnecting returns to the local catalogue without reloading the open project.

## Tasks / Subtasks

- [ ] Merge logic (AC: #1)
- [ ] Preference + marking in BlocksMenu (AC: #2)
- [ ] Library manager column/filter (AC: #3)
- [ ] Disconnect behaviour (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- `LibraryService_class` combines the repositories and feeds `BlockManager` and `SchemaManager`, so the editor catalogue no longer depends on where packages come from. [Source: architecture.md#adr-012]

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->
