# 1.1: Test harness: core library, Qt Test and CTest

**Story ID:** 1.1  
**Epic:** 1 — Foundation and conventions  
**Slug:** test-harness  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the STIx Config developer**,  
I want **a test target that links the same C++ core as the app**,  
so that **every later story can add unit tests without touching the app executable**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. The non-QML C++ sources (Document, Logger, DataTypes, SchemaManager, BlockManager, Project with Page/Tree/commands, ProjectManager, Application) are built as a static library target `stix_core`. `appSTIx_Config` links it and still builds and runs unchanged.
2. A CMake option `STIX_BUILD_TESTS` (default `ON`) adds `tests/`. `ctest` discovers and runs every test registered there.
3. A first test `tst_xmlnode` reads a small XML string into `XmlNode_class`, writes it back, and checks that elements, attributes (names, values, order) and unknown tags are preserved.
4. Tests can locate fixtures through a compile definition `STIX_FIXTURES_DIR` pointing to `tests/fixtures/`, which exists with a short `README.md`.
5. Adding a test later takes one call of a helper function `stix_add_test(<name> <sources…>)` in `tests/CMakeLists.txt`.
6. **Auto-discovery, so later stories never edit the shared CMake files:** `stix_core` sources are collected with `file(GLOB_RECURSE … CONFIGURE_DEPENDS)` from `src/Components/**`; QML files from `resources/qml/**` (Theme.qml keeps its singleton property); tests from `tests/unit/**/tst_*.cpp` and `tests/integration/**/tst_*.cpp`; `tests/tools/*.cmake` and `cmake/modules/*.cmake` are included automatically; `tools/*/` and `sdk/tests/` are added with `add_subdirectory` when they exist.

## Tasks / Subtasks

- [ ] Split the core sources into a `stix_core` static library (AC: #1)
  - [ ] Move the `SOURCES` from `qt_add_qml_module` into `add_library(stix_core STATIC …)`; link Qt6::Core, Gui, Xml (AC: #1)
  - [ ] Keep the QML module and resources on the app target; link `stix_core` (AC: #1)
- [ ] Add `tests/CMakeLists.txt` with `enable_testing()`, `find_package(Qt6 COMPONENTS Test)` and `stix_add_test()` (AC: #2, #5)
- [ ] Write `tests/unit/document/tst_xmlnode.cpp` (AC: #3)
- [ ] Create `tests/fixtures/README.md` and the `STIX_FIXTURES_DIR` definition (AC: #4)
- [ ] Auto-discovery of sources, QML, tests, `cmake/modules/`, `tools/` and `sdk/tests/` (AC: #6)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- The core library contains layers L1–L3 only. QML (L4) stays in the app target, and a file in layer N may include only layers ≤ N. [Source: architecture.md#2-architecture-pattern] [Source: architecture.md#adr-001]
- Keep CMake + Qt 6.11 + C++17 exactly as today (`qt_standard_project_setup(REQUIRES 6.11)`). [Source: architecture.md#adr-013]
- `QUndoStack` is in QtGui in Qt 6, so `stix_core` must link `Qt6::Gui`; no QtQuick dependency is allowed in it. [Inference] [Source: architecture.md#adr-001]
- The round-trip property tested here is the base of NFR-03 (unknown data kept 1:1 on save). [Source: architecture.md#adr-002]
- Test types planned by the architecture: unit tests for commands, migrations, `canConnect`, the validator and CBOR framing. This harness must make all of them possible. [Source: architecture.md#testing-strategy-planning-only]
- Auto-discovery is chosen so the 60 later stories can run in parallel without all editing `CMakeLists.txt`; an optional dependency gets its own `cmake/modules/<name>.cmake`. [Inference] (recorded in decision-log.md)

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** Qt Test unit tests run by CTest.
- **Key scenarios:** The app builds and runs; `ctest` finds `tst_xmlnode`; the round trip keeps the order and unknown tags.
- **Per-AC verification:** AC #1 → build both targets; launch the app and open an existing project; AC #2 → `ctest -N` lists the test; AC #3 → test asserts equality of re-serialised XML; AC #4 → test reads a file through `STIX_FIXTURES_DIR`; AC #5 → a dummy second test added with one line is discovered; AC #6 → add a dummy `.cpp`, a dummy `.qml`, a `tst_dummy.cpp` and a `cmake/modules/dummy.cmake` without touching CMakeLists: all are picked up after re-configure
- **Fixtures / mocks:** an inline XML string with an unknown element `<Foo Bar="1"/>`.
- **Edge cases to cover:** empty attributes, UTF-8 text (°, ², Cyrillic), self-closing elements.
