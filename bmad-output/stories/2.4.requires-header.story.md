# 2.4: Generate `<Requires>` on save

**Story ID:** 2.4  
**Epic:** 2 — Project file format v1.0.0  
**Slug:** requires-header  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **the project to always state exactly which library packages and versions it needs**,  
so that **the controller can check and install them before running it**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. On save, `Project/Requires` (first child of `Project`) lists one `Library` per package type used by the project (block types of `BlockInstance`s, periphery/protocol node types from library descriptors), with `Uuid`, `Name`, `Kind`, `Vers` and `Sha256`.
2. Package information comes from an interface `PackageInfoProvider` (L2). The first implementation reads BlockManager/SchemaManager descriptors (Sha256 is empty until packages exist); Epic 4 swaps in LibraryService without changing this code.
3. `Requires` is derived data: it is refreshed at save outside the undo stack (like `MDate`) and doesn't mark the project modified.
4. On load, a `Requires` that doesn't match the content is logged as a warning and corrected at the next save; a hand edit can't make it stay wrong.
5. Entries are sorted by `Kind`, then `Name`, for stable diffs.

## Tasks / Subtasks

- [ ] Define `PackageInfoProvider` and the descriptor-based implementation (AC: #2)
- [ ] Write `RequiresBuilder` (scans the tree, builds the node) (AC: #1, #5)
- [ ] Call it from save; replace the existing node (AC: #1, #3)
- [ ] Check on load + warning (AC: #4)
- [ ] Tests (AC: #1, #3, #4, #5)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- `Project/Requires/Library` lists every package used with `Uuid`, `Name`, `Kind`, `Vers`, `Sha256`; it is **generated on save** from the block and periphery types actually used, never maintained by hand, and regenerated if a hand edit makes it stale. [Source: architecture.md#adr-003]
- Package identity = `Uuid` + `Vers` (SemVer) + `Sha256`; kinds `Block`, `Periphery`, `Protocol`. [Source: architecture.md#adr-004]
- One version per project: one entry per `Uuid`. [Source: architecture.md#5-data-model]
- FR-13 depends on this header (exact-version check before upload, story 8.4). [Source: architecture.md#0-requirements-baseline]
- `Project_class::save` already sets `MDate` directly with `setValue` outside the undo stack; `Requires` follows the same precedent for derived data. [Inference] (from project.cpp)
