# 7.5: Set variables and parameters while connected

**Story ID:** 7.5  
**Epic:** 7 — Live monitoring and force  
**Slug:** set-variable-and-params  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to change a variable or a block parameter on the running controller**,  
so that **I can tune the installation live without uploading**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. While connected and in sync, editing a variable value sends `SetVariable {slot, value}`.
2. Editing a block parameter in the properties panel offers "Apply on controller", which sends `SetParams {iUuid, <XmlAttr>: value}`; the key is the exact XML attribute name.
3. The same change is applied to the local project as a normal undoable edit, so the local file stays equal to the controller's.
4. A refused key (unknown or wrong type) shows the controller's error naming the key.
5. Engineer role and above only.

## Tasks / Subtasks

- [ ] SetVariable (AC: #1)
- [ ] SetParams from the properties panel (AC: #2, #3)
- [ ] Error display (AC: #4)
- [ ] Role gating (AC: #5)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Message shape: one object keyed exactly like the XML — `{"iUuid": "…", "TempComfort": "22.5"}`; every other key is the exact attribute name; several keys allowed; STIx Config uses `SetParams`. [Source: architecture.md#adr-017]
- The controller applies it to the instance (`on_property`), writes the node through the instance's pointer, saves (debounced), increments `Rev` and pushes `ProjectChanged`. [Source: architecture.md#adr-017]
- Edits to the document go through undo commands. [Source: architecture.md#adr-002]
- After a successful SetParams, the editor's `BaseRev` should follow the controller's new `Rev` from the next `ProjectChanged`, because both sides are equal. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** integration tests against the mock.
- **Key scenarios:** set variable; set a parameter; refused key.
- **Per-AC verification:** AC #1 → mock receives SetVariable; AC #2 → mock receives SetParams with the exact key; AC #3 → local undo stack has the edit; AC #4 → mock refuses → error shown; AC #5 → Viewer disabled
- **Fixtures / mocks:** the mock.
- **Edge cases to cover:** editing while not in sync → option hidden.
