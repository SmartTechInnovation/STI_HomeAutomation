# 3.3: Draw wires and connect by dragging

**Story ID:** 3.3  
**Epic:** 3 — Wiring and validation in the editor  
**Slug:** connection-rendering  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to see wires between ports and to create one by dragging from an output to an input**,  
so that **wiring is visual and quick**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `DisplayConnections.qml` draws one curve per entry of `page.connections`, from the source port to the target port, coloured with `DataTypes.color(dataType)`.
2. Wires follow when a block or signal is moved.
3. Dragging from an output port and releasing on an input port calls `Project.cmdConnect`; releasing elsewhere does nothing.
4. Selecting a wire and pressing Delete calls `cmdDisconnect`.
5. Several wires into one input are all visible and individually selectable.

## Tasks / Subtasks

- [ ] Port anchor positions exposed from `Port.qml` / `Block.qml` / `Signal.qml` (AC: #1, #2)
- [ ] Curve drawing with `Shape` in `DisplayConnections.qml` (AC: #1, #5)
- [ ] Drag-to-connect interaction (AC: #3)
- [ ] Wire selection + Delete (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- QML holds only transient view state (hover, drag ghost); intents go up as `Q_INVOKABLE cmd*`; no QML computes business rules. [Source: architecture.md#adr-009]
- Data type colours come from `DataTypes_class::color`. [Source: architecture.md#component-datatypes-l2]
- Editor performance target 60 fps pan/zoom with 500 blocks. [Source: architecture.md#0-requirements-baseline]
- Use `QtQuick.Shapes` with a cubic path per wire; avoid a Canvas repaint of all wires per frame. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** a manual UI test checklist, plus a QML test for the drag→cmdConnect call using a mock Project.
- **Key scenarios:** draw, move, connect, disconnect.
- **Per-AC verification:** AC #1 → visual check with a fixture project; AC #2 → move a block: the wire follows; AC #3 → drag test → spy on cmdConnect; AC #4 → select + Delete → cmdDisconnect; AC #5 → 2 wires into 1 input, each selectable
- **Fixtures / mocks:** the 2.3 fixture.
- **Edge cases to cover:** zoomed-out canvas; a wire to a block off screen.
