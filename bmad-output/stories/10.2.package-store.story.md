# 10.2: Package store: install, verify, list, remove

**Story ID:** 10.2  
**Epic:** 10 — STIx Runtime MVP (separate repository `stix-runtime`)  
**Slug:** package-store  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the controller**,  
I want **to store library packages side by side by version and only accept verified ones**,  
so that **projects get exactly the builds they require**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Packages are stored in `/var/lib/stix/packages/<Uuid>/<Vers>/` (root configurable for tests); several versions live side by side.
2. Install verifies every file's SHA-256 and the Ed25519 `SIGNATURE` against the trusted keys; unsigned packages only in developer mode.
3. Install is atomic (temp dir + rename); path traversal is rejected.
4. `list()` returns `{uuid, name, kind, vers, sha256, licence}`; `remove()` is refused while the running project requires that version.
5. Only the binary for the controller's own target triple is required; others may be skipped on install to save flash.

## Tasks / Subtasks

- [ ] Store layout + list (AC: #1, #4)
- [ ] Verify (hash + signature) (AC: #2)
- [ ] Atomic install + traversal check (AC: #3)
- [ ] Remove with in-use check (AC: #4)
- [ ] Target filtering (AC: #5)
