# 1.7: Translations: EN / RU / RO / ES with a live language switch

**Story ID:** 1.7  
**Epic:** 1 — Foundation and conventions  
**Slug:** translations-pipeline  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to use STIx Config in my language**,  
so that **the tool is usable in the markets it targets**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `qt_add_translations` builds `i18n/stix_en.ts`, `stix_ru.ts`, `stix_ro.ts`, `stix_es.ts` into the app; `lupdate` collects every `qsTr`/`tr` string.
2. Setting `Application.Language` (EN, RU, RO, ES) installs the matching `QTranslator` and calls `QQmlEngine::retranslate()`; the visible UI changes language without a restart.
3. The chosen language is saved in `Config.xml` and restored at the next start.
4. An untranslated string falls back to English, never to an empty label.

## Tasks / Subtasks

- [ ] Add `qt_add_translations` and the 4 `.ts` files (AC: #1)
- [ ] Install the translator and retranslate on `languageChanged` (AC: #2)
- [ ] Persist the language through the existing `saveConfig`/`loadConfig` (AC: #3)
- [ ] Verify the fallback (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- FR-16: multi-language UI (EN, RU, RO, ES); the near-term plan includes setting up `qt_add_translations`. [Source: architecture.md#0-requirements-baseline] [Source: architecture.md#11-future-considerations]

- State belongs to C++; QML only binds (ADR-009). The translator lives in C++, and QML only calls the property setter. [Source: architecture.md#adr-009]
- This is the *UI* language. The project's own `Language` property (Project schema, `Project_EN.xml`) is a different thing and is not changed here. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** unit test of the switch, plus a manual UI check.
- **Key scenarios:** switch EN→RO→EN at run time; restart keeps RO.
- **Per-AC verification:** AC #1 → the build produces `.qm` files; AC #2 → test that `QCoreApplication::translate` returns the RO text after the switch; AC #3 → restart and check the setting; AC #4 → remove one RO entry: the English text shows
- **Fixtures / mocks:** one translated sample string per language.
- **Edge cases to cover:** switching while a dialog is open.
