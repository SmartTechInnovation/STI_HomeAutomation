# 1.4: Fix the non-inline header function and the `Application` global name

**Story ID:** 1.4  
**Epic:** 1 — Foundation and conventions  
**Slug:** header-and-global-fixes  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the STIx Config developer**,  
I want **headers that can be included from several files and one naming rule for globals**,  
so that **adding new translation units never causes link errors and the code reads consistently**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `resolveResourceUrl` is declared in `resourceurl.h` and defined either `inline` there or in a new `resourceurl.cpp`; including the header from two `.cpp` files links without duplicate symbols.
2. The global `Application` object is renamed `S_Application` in C++ (declaration, definition and all uses: `main.cpp`, `schemamanager.cpp`).
3. The QML singleton name stays `Application`, so no QML file changes.
4. The app builds and behaves as before (language config loads, schema `Project_EN.xml` is found).

## Tasks / Subtasks

- [ ] Make `resolveResourceUrl` non-ODR-violating (AC: #1)
  - [ ] Add a test translation unit including the header, linked into `tst_resourceurl` (AC: #1)
- [ ] Rename `Application` → `S_Application` (AC: #2, #3)
- [ ] Smoke-check that the app runs (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Known violation: `resourceurl.h` defines a non-inline function in a header, which causes ODR/link errors once two translation units include it. [Source: architecture.md#adr-011]
- Known violation: `Application` (global) lacks the `S_` prefix; globals are `S_PascalCase`. [Source: architecture.md#adr-011]
- Singletons are registered in `main.cpp` under `STI.<Name>` URIs; the registered name is what QML sees. [Source: architecture.md#adr-009]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** a link test plus a smoke run.
- **Key scenarios:** two TUs include the header; the app still runs.
- **Per-AC verification:** AC #1 → `tst_resourceurl` links two TUs and resolves a relative icon path; AC #2 → grep `\bApplication\.` in src finds nothing; AC #3 → grep QML: unchanged; AC #4 → manual smoke run
- **Fixtures / mocks:** a fixture descriptor folder with an icon.
- **Edge cases to cover:** `qrc:` paths and absolute paths in `resolveResourceUrl`.
