# 1.3: Block descriptors match what BlockManager reads

**Story ID:** 1.3  
**Epic:** 1 — Foundation and conventions  
**Slug:** descriptor-attribute-fix  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **every block to load with its port titles, short names and data types**,  
so that **wires can be type-checked and blocks are shown correctly**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. All 10 block descriptors under `templates/blocks/**/Descriptor.xml` use `Title=` (not `ExtName=`), `ShortName=` (not `ShortTitle=`) and `DataType=` (not `Type=`) on `Input`, `Output` and `Property` elements.
2. The stray attribute `T` on the "Off / Lock" input of `Garage_Gate` is removed.
3. Every block `Vers` is SemVer `MAJOR.MINOR.PATCH` (`1.0` → `1.0.0`).
4. `BlockManager` logs a `Log::Warning` naming the file, the port and the attribute for any attribute it does not recognise on a port.
5. After loading, every port of every template block has a non-empty `DataType`, `ShortName` and `Title`; a unit test asserts this.

## Tasks / Subtasks

- [ ] Rename the attributes in the 10 descriptors (AC: #1, #2)
- [ ] Update `Vers` to SemVer (AC: #3)
- [ ] Add the known-attribute whitelist and warning in `BlockManager_class::loadBlockType` (AC: #4)
- [ ] Add `tests/unit/blockmanager/tst_blockdescriptors.cpp` loading `templates/blocks` (AC: #5)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Known violation: `Garage_Gate/Descriptor.xml` uses `ShortTitle=` and `Type=` on ports while `BlockManager` reads `ShortName` and `DataType`, and it has a stray attribute `T`. [Source: architecture.md#adr-011]
- Scan at planning time: across the 10 descriptors, 70 ports use `Type=`, 44 use `ExtName=`, 26 use `ShortTitle=`. `BlockManager` reads `ATTR_TITLE`, `ATTR_SHORT_NAME`, `ATTR_DATA_TYPE`, so today all data types are lost. [Inference] (from a code scan on 2026-11-05)
- Fixing the files (not the reader) is chosen because `DataType` and `ShortName` are the contract names in the tokens and the ABI port order. [Source: architecture.md#adr-006] [Source: architecture.md#adr-011]
- Versions are SemVer everywhere. [Source: architecture.md#adr-011] [Source: architecture.md#adr-004]
- Data type names must be those of `DataTypes_class` (`Void`, `Bool`, `Int`, `Float`, `String`, `Enum`, `Date`, `Custom`). [Source: architecture.md#component-datatypes-l2]
- Log through `S_Logger.write(Log::Warning, BLOCK_MANAGER_NAME, …)` once, where detected. [Source: architecture.md#adr-010]
