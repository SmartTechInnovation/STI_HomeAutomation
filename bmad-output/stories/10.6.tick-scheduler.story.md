# 10.6: Tick scheduler: `run()` every `TickMs`

**Story ID:** 10.6  
**Epic:** 10 — STIx Runtime MVP (separate repository `stix-runtime`)  
**Slug:** tick-scheduler  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **a block with a state machine**,  
I want **my `run()` to be called at the period my descriptor declares**,  
so that **timed behaviour works without busy loops**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. The RuntimeManager reads `TickMs` per block type from the descriptor and calls `run(now)` on each instance with `TickMs > 0`, using a timer wheel with 10 ms resolution.
2. Instances with `TickMs = 0` are never ticked.
3. `run` goes through the same busy/mailbox protection as `on_input`.
4. With no events and no ticks due, the thread sleeps (no polling); tick jitter stays within ±10 ms under normal load.

## Tasks / Subtasks

- [ ] Timer wheel (AC: #1, #4)
- [ ] Schedule from descriptors (AC: #1, #2)
- [ ] Use the dispatch protection (AC: #3)
- [ ] Jitter test (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Tick: a block type declares `TickMs` in its descriptor; the RuntimeManager calls `run(now)` every `TickMs` with a timer wheel of 10 ms resolution; `TickMs="0"` (default) = never ticked. [Source: architecture.md#adr-005]
- Target tick jitter ±10 ms; idle CPU < 2 %. [Source: architecture.md#0-requirements-baseline]
- The RuntimeManager sleeps until the next tick or Link command. [Source: architecture.md#7-fr--nfr-coverage-matrix]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** unit tests with a fake clock, plus a jitter measurement on real time.
- **Key scenarios:** 100 ms and 1,000 ms blocks; idle.
- **Per-AC verification:** AC #1 → call counts with the fake clock; AC #2 → 0 → never; AC #3 → concurrent emit + tick → no double entry; AC #4 → jitter histogram
- **Fixtures / mocks:** a counting tick plugin.
- **Edge cases to cover:** TickMs smaller than the resolution (→ rounded up to 10 ms, warning).
