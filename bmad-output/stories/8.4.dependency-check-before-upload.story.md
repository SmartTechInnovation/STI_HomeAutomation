# 8.4: Check and install exact dependencies before upload

**Story ID:** 8.4  
**Epic:** 8 — Controller libraries and dependency check  
**Slug:** dependency-check-before-upload  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **the upload to make sure the controller has exactly the package versions my project requires**,  
so that **the program never runs against a wrong library build**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Before `UploadProject`, the editor sends `CheckProject {requires}` with the project's `<Requires>`.
2. Missing or mismatched packages are listed ("Garage_Gate 1.0.0 missing", "ModbusTcp: controller has 2.3.0, project needs 2.3.1"); "Install and upload" installs them (8.3) from the local library, then uploads.
3. A required package not available locally either stops the upload with a clear message.
4. Nothing is uploaded while any dependency is unresolved.

## Tasks / Subtasks

- [ ] CheckProject call in the upload pipeline (AC: #1)
- [ ] Dependency dialog (AC: #2)
- [ ] Install then upload (AC: #2, #4)
- [ ] Unavailable-package handling (AC: #3)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Upload flow: `CheckProject` → for each missing or mismatched package, `InstallLibrary` → `UploadProject` → swap → `GetSymbols` → `Subscribe`. [Source: architecture.md#6-1-stix-link-messages-protocol-v1]
- FR-13 / NFR-06: exact versions, identity Uuid + Vers + Sha256. [Source: architecture.md#adr-004] [Source: architecture.md#0-requirements-baseline]
- `<Requires>` is generated on save (2.4). [Source: architecture.md#adr-003]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** integration tests against the mock.
- **Key scenarios:** all present; one missing; one mismatched; unavailable.
