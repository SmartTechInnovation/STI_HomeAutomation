# 6.3: `ControllerLink`: TLS 1.3 connection on its own thread

**Story ID:** 6.3  
**Epic:** 6 — Controller connection (editor side)  
**Slug:** controller-link-connect  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **STIx Config to connect to my controller over an encrypted link**,  
so that **configuration and monitoring are secure**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `ControllerLink_class` (L3) runs its `QSslSocket` on a dedicated `QThread`, connects with TLS 1.3 only, and performs `Hello` (protocol version check: a different MAJOR → refuse with a clear message).
2. It exposes `state` (Disconnected, Connecting, Connected, Error), `controllerInfo` (serial, model, runtime version) and `lastError` as `Q_PROPERTY`s, updated through queued signals.
3. The host comes from `RootDevice/@IpAddress` and the port from `RootDevice/@PortLink` (new token, default 9443).
4. Requests return a `requestId` and complete through `replied(requestId, result)`; a timeout (default 10 s) completes with `ErrorCode_e::Timeout`.
5. Lost connections go to `Error` with the reason, and no automatic reconnect loop floods the log.
6. It is registered in `main.cpp` as `STI.ControllerLink`.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- In the editor everything is handled by `ControllerLink_class` (L3) on its own `QThread`; the UI sees only properties and signals. [Source: architecture.md#adr-007]
- Transport TCP + TLS 1.3 (`QSslSocket`); port configured on `RootDevice/@PortLink` (new attribute; default 9443). [Source: architecture.md#adr-007]
- Long-running work runs off the GUI thread; results come back as queued signals. [Source: architecture.md#adr-009]
- Errors: `Result_s`/`ErrorCode_e`, logged once. [Source: architecture.md#adr-010]
- Add the token `ATTR_PORT_LINK` to `sdk/stix_tokens.h` first. [Source: architecture.md#adr-011]
- Certificate trust is handled in 6.4. In this story, accept the certificate only in a debug build with an explicit flag, so the TLS path can be tested. [Inference]
