# 1.6: CI: build and test on Windows, macOS and Linux

**Story ID:** 1.6  
**Epic:** 1 — Foundation and conventions  
**Slug:** ci-matrix  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the STIx Config developer**,  
I want **every push built and tested on the three desktop OSes**,  
so that **platform breakages are caught immediately, not at release time**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. A GitHub Actions workflow builds the app and runs `ctest` on Windows (MSVC 2022 x64), macOS (arm64) and Linux (GCC x86-64) for every push and pull request.
2. A CMake option `STIX_WERROR` turns warnings into errors; CI enables it.
3. Qt 6.11 is installed with caching, so a warm run doesn't re-download Qt.
4. The workflow fails if any test fails, and test logs are uploaded as artifacts.

## Tasks / Subtasks

- [ ] Write `.github/workflows/ci.yml` with the 3-OS matrix (AC: #1, #4)
- [ ] Add `STIX_WERROR` (MSVC `/W4 /WX`, GCC/Clang `-Wall -Wextra -Werror`) (AC: #2)
- [ ] Cache the Qt install (AC: #3)
- [ ] Fix any warnings that block the first green run (AC: #2)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- CI matrix: Windows (MSVC 2022, x64), macOS (arm64 + x86-64 universal), Linux (GCC, x86-64); warnings as errors in CI. [Source: architecture.md#adr-013]
- OS-specific code may live only in `src/Platform/`; CI is where violations surface. [Source: architecture.md#adr-013]
- A macOS universal build can be added in the packaging story; arm64 is enough for CI. [Inference]
- Use a maintained Qt installer action and pin its version; check that Qt 6.11 is available for all 3 runners. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** the workflow itself is the test.
- **Key scenarios:** green on all 3 OSes; a deliberately failing test makes CI red.
- **Per-AC verification:** AC #1 → 3 green jobs; AC #2 → inject a warning on a branch → red; AC #3 → compare the times of a cold and a warm run; AC #4 → inject a failing test → red, with the logs artifact present
- **Fixtures / mocks:** none.
- **Edge cases to cover:** paths with spaces on Windows; case-sensitive includes on Linux.
