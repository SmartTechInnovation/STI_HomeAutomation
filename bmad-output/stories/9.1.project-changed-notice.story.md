# 9.1: "Project edited on the controller": notice and download

**Story ID:** 9.1  
**Epic:** 9 — Project sync and merge  
**Slug:** project-changed-notice  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to be told when the project was edited on the controller**,  
so that **I download the latest version before I continue programming**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. A `ProjectChanged {rev, hash}` push for the connected controller shows a non-blocking notice: "The project was edited on the controller (rev N). Download the latest version?"
2. Accepting downloads it: if the local project has no unsaved changes, it is replaced in the same tab; otherwise it opens in a new tab and the engineer is pointed to Merge (9.3).
3. After download, `BaseRev` equals the controller `Rev`.
4. Repeated pushes while the notice is open update the same notice (no stacking).

## Tasks / Subtasks

- [ ] Handle the push in ProjectSync (AC: #1, #4)
- [ ] Notice UI (AC: #1)
- [ ] Download path choice (AC: #2, #3)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- After each save the controller pushes `ProjectChanged {rev, hash}`; STIx Config shows "The project was edited on the controller (rev N). Download the latest version?" [Source: architecture.md#adr-017]
- `ProjectSync` tracks `BaseRev` per project and controller and offers the download on `ProjectChanged`. [Source: architecture.md#component-projectsync-l3-new]
- `BaseRev` storage: `SyncState_class` (2.5). [Source: epics.md#epic-2]
- Expose `ProjectSync` as a property of `ControllerLink` (`ControllerLink.sync`) instead of registering a new singleton in `main.cpp`. [Inference]
