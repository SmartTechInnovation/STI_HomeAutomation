# 4.6: Library manager screen

**Story ID:** 4.6  
**Epic:** 4 — Library packages and catalogue (editor)  
**Slug:** library-manager-ui  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **one screen that lists my packages and lets me install and remove them**,  
so that **I can manage libraries without touching folders**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. A Library page lists the catalogue from `LibraryService`: name, kind, version, source (Templates / Local / later Controller), signed status, search by name.
2. "Install package…" opens a file dialog for `.stixpkg` and shows progress and errors in `LogTab`.
3. "Remove" asks for confirmation and is disabled for template packages and for versions an open project requires.
4. The page is reachable from the home page and from the editor top bar.

## Tasks / Subtasks

- [ ] `LibraryPage.qml` with list and search (AC: #1)
- [ ] Install flow (AC: #2)
- [ ] Remove flow (AC: #3)
- [ ] Navigation entries (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- UI code never reads library folders directly; it goes through `LibraryService`. [Source: architecture.md#adr-012]
- QML binds to properties and calls methods; no business rules in QML. [Source: architecture.md#adr-009]
- Errors go to `LogTab`; modal dialogs only for data-loss prompts (remove = data loss → confirm). [Source: architecture.md#adr-010]
- The "source" column prepares FR-15 (controller catalogue) in Epic 8. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** a manual UI checklist plus a QML test for the model binding.
- **Key scenarios:** list, search, install, remove.
- **Per-AC verification:** AC #1 → visual check with 2 sources; AC #2 → install a fixture package; AC #3 → remove disabled for a template and a required version; AC #4 → navigate from both places
- **Fixtures / mocks:** fixture packages.
- **Edge cases to cover:** a long list (200 packages) scrolls smoothly.
