# 10.11: `SetParams` / `HmiSetParams`: instance + XML node, debounced save, `Rev`

**Story ID:** 10.11  
**Epic:** 10 — STIx Runtime MVP (separate repository `stix-runtime`)  
**Slug:** set-params-and-save  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an end user or engineer**,  
I want **a changed parameter (e.g. TempComfort 22.5) to take effect at once and be saved**,  
so that **settings changed on the controller survive restarts and reach STIx Config**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `SetParams {iUuid, <XmlAttr>: value, …}` (Engineer) and `HmiSetParams` (HmiUser: only `Ui="Write"` parameters allowed by Rights) find the instance by `iUuid`, check each key against the descriptor and type, call `on_property(idx, value)`, and write the attribute through the instance's XML-node pointer.
2. A refused key returns an `Error` naming it; accepted keys in the same message still apply.
3. `host->set_property` from a block follows the same path.
4. When modified, `current/Project.xml` is saved at most once every 10 s and on clean shutdown, atomically; `Rev` increments; `ProjectChanged {rev, hash}` is pushed to all clients.
5. No storage write happens per message.

## Tasks / Subtasks

- [ ] Key resolution + checks (AC: #1, #2)
- [ ] on_property + node write (AC: #1, #3)
- [ ] Debounced atomic save + Rev (AC: #4, #5)
- [ ] ProjectChanged push (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Message keyed exactly like the XML: `{"iUuid": "01a0f27a-…", "TempComfort": "22.5"}`; find instance by iUuid → check key (descriptor parameter, type; HMI: `Ui="Write"` + Rights) → `on_property` → write the attribute through the node pointer → mark modified. [Source: architecture.md#adr-017]
- Saving: at most once every 10 s and on clean shutdown; atomic temp + rename; `Rev` +1; then `ProjectChanged {rev, hash}`. [Source: architecture.md#adr-017]
- Only attribute values of existing elements change on the controller; structure only by upload. [Source: architecture.md#adr-017]
- The writer follows the ADR-003 style rules (stable attribute order, unknown data kept). [Source: architecture.md#adr-003]
