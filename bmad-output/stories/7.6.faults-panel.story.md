# 7.6: Faults: list, show and clear

**Story ID:** 7.6  
**Epic:** 7 — Live monitoring and force  
**Slug:** faults-panel  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to see which block instances were quarantined and why, and to clear them**,  
so that **I can find and fix looping, hanging or crashing blocks**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `Fault` pushes and `ListFaults` results appear in `LogTab` with instance title, page, reason (recursion, crash, hang), call chain and the last log lines.
2. Clicking a fault selects the instance on its page.
3. "Clear fault" (one or all) sends `ClearFault`; the marker disappears once the controller confirms.
4. Runtime `Log` pushes are shown in `LogTab`, tagged with the controller name.

## Tasks / Subtasks

- [ ] Fault model fed by the Link (AC: #1)
- [ ] LogTab integration + select-on-click (AC: #1, #2)
- [ ] ClearFault (AC: #3)
- [ ] Runtime Log push (AC: #4)
