# 6.1: STIx Link frame codec and messages (CBOR)

**Story ID:** 6.1  
**Epic:** 6 — Controller connection (editor side)  
**Slug:** link-framing-cbor  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the STIx Config developer**,  
I want **a tested codec for STIx Link frames and messages**,  
so that **every Link feature builds on one correct wire format**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `LinkCodec` encodes and decodes frames `uint32 length (big-endian) | CBOR map {t, id, p}` with `QCborStreamWriter`/`QCborValue`, and rejects frames larger than a configurable maximum (default 1 MiB).
2. A streaming decoder accepts partial reads and yields complete frames.
3. Message type constants and typed structs exist for every message in architecture §6.1 (requests, responses, pushes), with `toCbor()` / `fromCbor()`.
4. Chunked transfer helpers split payloads into 64 KiB chunks and verify the final SHA-256.
5. Values use the same type tags as `stix_value`.
6. Unit tests cover round trips of every message, partial reads, oversize frames and chunking.

## Tasks / Subtasks

- [ ] Frame codec + streaming decoder (AC: #1, #2)
- [ ] Message catalogue from §6.1 (AC: #3, #5)
- [ ] Chunk helpers (AC: #4)
- [ ] Tests (AC: #6)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Framing: `uint32 length (big-endian) | CBOR map`, each message with `t` (type), `id` (request id, 0 for push) and `p` (payload); large transfers chunked into 64 KiB with a final SHA-256; protocol version negotiated in `Hello`; within MAJOR 1 only additive changes. [Source: architecture.md#adr-007]
- Message table (Hello, Auth, GetInfo, ListLibraries, InstallLibrary, RemoveLibrary, CheckProject, UploadProject, DownloadProject, ActivatePrevious, GetSymbols, Subscribe, Unsubscribe, Force, Release, ListFaults, ClearFault, SetVariable, SetParams, GetBase, Hmi*, ValueBatch, Log, State, ProjectChanged, Fault, Error). [Source: architecture.md#6-1-stix-link-messages-protocol-v1]
- The Link stays on CBOR (binary JSON with the same keys). [Source: decision-log.md#adr-007-encoding]
- Values on the wire use the same type tags as the ABI `stix_value`. [Source: architecture.md#adr-007]
- Codec code is L3 (`ControllerLink`) but has no Qt Network dependency, so the mock controller (6.2) reuses it. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** unit tests.
- **Key scenarios:** round trip per message; byte-by-byte feed; oversize; chunk + hash.
- **Per-AC verification:** AC #1 → encode/decode equality; AC #2 → feed 1 byte at a time; AC #3 → 2 MiB frame rejected; AC #4 → corrupted chunk → hash mismatch; AC #5 → type tag table test; AC #6 → all pass
- **Fixtures / mocks:** generated messages.
- **Edge cases to cover:** an unknown `t` (must be skipped, not fatal); id overflow.
