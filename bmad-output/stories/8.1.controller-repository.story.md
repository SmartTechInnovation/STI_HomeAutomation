# 8.1: `ControllerRepository`: the controller's packages over the Link

**Story ID:** 8.1  
**Epic:** 8 — Controller libraries and dependency check  
**Slug:** controller-repository  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **STIx Config to read the packages installed on the connected controller**,  
so that **I design with exactly what the controller can run**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `ControllerRepository` implements `LibraryRepository` over `ControllerLink`: `list()` → `ListLibraries`; `fetchDescriptor`/`fetchPackage` download the descriptor, icons and `ui/` files.
2. Downloaded files are cached in `AppLocalDataLocation/cache/controllers/<serial>/<Uuid>/<Vers>/`, verified by SHA-256, and reused while the Sha256 doesn't change.
3. It appears in `LibraryService` when connected and disappears (cache kept) when disconnected.
4. Errors (not connected, Forbidden) come back as `Result_s` through the repository signals.

## Tasks / Subtasks

- [ ] Repository implementation (AC: #1, #4)
- [ ] Cache (AC: #2)
- [ ] Connect/disconnect wiring in LibraryService (AC: #3)
