# 10.9: Upload with `baseRev`, atomic swap, previous and Base copies

**Story ID:** 10.9  
**Epic:** 10 — STIx Runtime MVP (separate repository `stix-runtime`)  
**Slug:** upload-swap-persistence  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **an upload to replace the running program safely**,  
so that **a bad project never leaves the controller without a working program**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `UploadProject` (chunked, SHA-256 verified) with `baseRev`: if the current `Rev` is newer and `force` is false → `RevConflict {rev}`.
2. The new project is loaded and wired next to the running one (10.3/10.4); on success it is swapped in between two events; on failure the old one keeps running and `Error {loadErrors[]}` is returned.
3. Files: `current/Project.xml`, `previous/` (the last good project) and `base/Project.xml` (exactly the uploaded XML, for merges), written atomically.
4. `DownloadProject`, `GetBase` and `ActivatePrevious` (same swap path) work; a successful upload returns `{ok, rev, symbolTable}`.
5. The program runs at all times; there is no start or stop. After a reboot the current project starts automatically.

## Tasks / Subtasks

- [ ] Autostart (AC: #5)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Atomic deployment: the new project is loaded and wired next to the running one, then swapped in between two events; if loading fails, the old one keeps running and the errors go back; the last good project is stored on disk. [Source: architecture.md#adr-005]
- The controller keeps Base (the exact XML of the last upload) next to the current one; `UploadProject` with an older `baseRev` → `RevConflict`; `force:true` overwrites. [Source: architecture.md#adr-017]
- FR-09: always running; restarts only on upload. [Source: architecture.md#0-requirements-baseline]
- Storage paths under `/var/lib/stix/project/`. [Source: architecture.md#5-data-model]
