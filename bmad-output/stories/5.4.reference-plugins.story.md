# 5.4: Reference plugins: And, Or, Add, virtual I/O driver

**Story ID:** 5.4  
**Epic:** 5 — Plugin SDK and C ABI  
**Slug:** reference-plugins  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **a block author**,  
I want **working examples of blocks and a driver**,  
so that **I can copy a correct pattern instead of guessing**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `sdk/examples/and`, `or`, `add` implement the existing template blocks (same Uuid and ports as `templates/blocks/Logic/And`, …), using the AND-style fan-in map (all sources of an input combined).
2. `sdk/examples/virtual-io` is a driver plugin for `VirtualIn`/`VirtualOut` channels that calls `emit_signal` for inputs and accepts `write` for outputs.
3. Each example has a `Descriptor.xml` + `manifest.xml` and builds into a `.stixpkg` with 5.3.
4. Unit tests with the fake host show: And with 2 sources on I1 and 1 on I2 gives the correct result; Add sums; virtual-io round-trips a value.
5. Each example has a short README explaining the pattern it shows.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Fan-in is the block's decision: AND keeps a map of all sources on an input and evaluates them together; Lighting acts on the last event. [Source: architecture.md#adr-005] [Source: architecture.md#6-2-plugin-c-abi-v1]
- Drivers send every incoming value with `host->emit_signal`; callbacks run inline. [Source: architecture.md#adr-006]
- Port order in the ABI equals the element order in `Descriptor.xml`. [Source: architecture.md#adr-006]
- These examples later become the first packages the runtime (10.3) loads in its integration tests. [Inference]
