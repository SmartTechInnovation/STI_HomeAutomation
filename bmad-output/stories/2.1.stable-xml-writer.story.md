# 2.1: Stable, diff-friendly XML writer

**Story ID:** 2.1  
**Epic:** 2 — Project file format v1.0.0  
**Slug:** stable-xml-writer  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator who keeps projects in git**,  
I want **saving the same project to always produce the same bytes, on every OS**,  
so that **diffs show only real changes and I can edit the file by hand when debugging**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Attributes are written in a stable order: `IUuid`, `Uuid`, `Title`, then the others in schema/descriptor order. Attributes the schema doesn't know keep their relative order and come after the known ones.
2. UUID-valued attributes (`IUuid`, `Uuid`, `Ref`, `Io`) are written lowercase, without braces.
3. Output is UTF-8, with a 4-space indent and **LF** line endings on Windows, macOS and Linux (no `QIODevice::Text` on write).
4. Saving twice in a row gives byte-identical files (apart from `MDate`), and unknown elements and attributes are kept.
5. The ordering rule is supplied by the Project layer (L2) to the Document writer (L1) as a callback, so `XmlNode_class` does not depend on `SchemaManager`.

## Tasks / Subtasks

- [ ] Add a write-options/ordering callback to `XmlNode_class::write` (AC: #1, #5)
- [ ] Implement the order in Project using SchemaManager and BlockManager metadata (AC: #1)
- [ ] Normalise UUID attributes on write (AC: #2)
- [ ] Remove `QIODevice::Text` from `Project_class::save`; verify the indent and encoding (AC: #3)
- [ ] Idempotence and unknown-data tests (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Style rules: UTF-8, 4-space indent, one element per entity, scalars as attributes, no blobs, no default namespaces; the writer emits attributes in a **stable order** (`IUuid`, `Uuid`, `Title`, then schema order) so files diff cleanly in git. [Source: architecture.md#adr-003]
- Identity: `IUuid` values are lowercase RFC-4122 strings without braces. [Source: architecture.md#adr-003]
- Unknown elements and attributes are kept 1:1 on save. [Source: architecture.md#adr-002]
- Layering: Document is L1, Project is L2; dependencies point downwards only, hence the callback. [Source: architecture.md#2-architecture-pattern]
- Today `Project_class::save` opens the `QSaveFile` with `QIODevice::Text`, which writes CRLF on Windows. The same project would then differ on every line between Windows and macOS. [Inference] (from project.cpp)
- Keep the existing `.bak` copy and the `QSaveFile` atomic commit. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** unit tests on Document and Project save.
- **Key scenarios:** reordered input becomes ordered; double save is identical; unknown data survives.
- **Per-AC verification:** AC #1 → fixture with shuffled attributes → expected order; AC #2 → `{ABC-…}` → `abc-…`; AC #3 → check the bytes contain no `\r\n` (run in CI on Windows); AC #4 → save, save again, compare bytes; AC #5 → build check: `xmlnode.h` includes no L2 header
- **Fixtures / mocks:** a small project with an unknown `<Custom X="1"/>` element and shuffled attributes.
- **Edge cases to cover:** attributes not in any schema; elements with no IUuid.
