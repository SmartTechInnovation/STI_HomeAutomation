# 7.2: `LiveValues_class`: frame-coalesced live values

**Story ID:** 7.2  
**Epic:** 7 — Live monitoring and force  
**Slug:** live-values-model  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the editor UI**,  
I want **one model holding the latest value, force and fault flags per item**,  
so that **QML updates smoothly without touching the document**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `LiveValues_class` (L3) stores `{value, type, forced, fault, ts}` per `IUuid` from `ValueBatch`.
2. Updates are coalesced: QML is notified **at most once per frame** (~16 ms), whatever the batch rate.
3. Live values never enter the document tree: no undo entries, no `modified` flag.
4. QML can bind per item (`LiveValues.value(iUuid)` with a change notification) without rebuilding a whole list.
5. Registered as `STI.LiveValues`.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Live monitor values go into a dedicated `LiveValues_class` model keyed by `IUuid`, updated **at most once per frame** from `ValueBatch`; they never go into the document tree (no undo entries, no `modified` flag). [Source: architecture.md#adr-009]
- `LiveValues` keeps the latest value plus the force and fault flags. [Source: architecture.md#component-livevalues-l3-new]
- A per-item binding can use a small `QObject` per subscribed item, or a `QQmlPropertyMap`; choose whichever keeps 500 items at 60 fps. [Inference]

## Testing

- **Approach:** unit tests plus a micro-benchmark.
- **Key scenarios:** 1,000 updates within 16 ms → 1 notification; document untouched.
- **Per-AC verification:** AC #1 → store/read; AC #2 → QSignalSpy count per frame; AC #3 → undo count and modified unchanged; AC #4 → QML binding test; AC #5 → import smoke test
- **Fixtures / mocks:** synthetic batches.
- **Edge cases to cover:** a type change for a slot (after re-upload).
