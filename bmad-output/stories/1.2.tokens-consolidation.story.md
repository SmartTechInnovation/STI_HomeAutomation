# 1.2: One definition per XML token: `sdk/stix_tokens.h` + editor-only `project_tokens.h`

**Story ID:** 1.2  
**Epic:** 1 — Foundation and conventions  
**Slug:** tokens-consolidation  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the STIx Config developer**,  
I want **every XML tag and attribute name defined exactly once**,  
so that **the editor, the runtime and plugins share one contract and macros can never disagree**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `sdk/stix_tokens.h` (MIT licence header) defines every name of the program contract: the Project.xml structure tokens (`Project`, `RootDevice`, `Program`, `Page`, `BlockInstance`, `SignalInRef`, `SignalOutRef`, `Input`, `Output`, `Property`, `Source`, `Requires`, `Library`), the attributes used by them (`Uuid`, `IUuid`, `Title`, `Ref`, `Io`, `Px`, `Py`, `Width`, `ShortName`, `Value`, `DataType`, `ConfigVers`, `Rev`, `Vers`, `Sha256`, `Kind`, `Ui`, `TickMs`) and the schema tags (`NodeType`, `Group`, `Variant`, `Child`…).
2. `project_tokens.h` keeps only editor-side metadata (company, client, units, rooms, users…) and contains no name that is also in `sdk/stix_tokens.h`.
3. `document_tokens.h` is removed, and every former include now includes the right header.
4. Each `TOKEN_`/`ATTR_`/`TAG_`/`IO_` macro name is defined in exactly one header; a CTest check fails if any name is defined twice.
5. The app builds, and opening, editing and saving an existing project produces the same file as before this change.

## Tasks / Subtasks

- [ ] Create `sdk/stix_tokens.h`, with an MIT header, from the program-contract names in `document_tokens.h` and `project_tokens.h` (AC: #1)
- [ ] Reduce `project_tokens.h` to editor-only names (AC: #2)
- [ ] Remove `document_tokens.h`; fix the includes in project.cpp, page.cpp, projecttree.cpp, schemamanager.cpp, blockmanager.cpp, projectmanager.cpp, xmlnode (AC: #3, #5)
- [ ] Add `tests/tools/check_tokens.cmake` (or a small script) registered with CTest that scans the headers for duplicate macro names (AC: #4)
- [ ] Add the new names `Requires`, `Library`, `Rev`, `Vers`, `Sha256`, `Kind`, `Ui`, `TickMs` (they are needed by Epics 2 and 4) (AC: #1)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Known violation to fix: `ATTR_REF` is defined twice, and `TOKEN_PROJECT`, `ATTR_ROOM` and others are duplicated across `document_tokens.h` and `project_tokens.h`. Merge them into `sdk/stix_tokens.h` (program/runtime contract) and `project_tokens.h` (editor-only metadata). [Source: architecture.md#adr-011]
- `stix-sdk` holds plain C/C++ headers (XML tokens, value types, ABI). It starts in this repo at `sdk/`, is MIT-licensed, and later moves to its own repo. [Source: architecture.md#adr-001] [Source: architecture.md#adr-014]
- Rule: a new XML name is first added to the tokens header and then used; XML string literals appear in C++ only through these macros. [Source: architecture.md#adr-011]
- Element and attribute names in Project.xml (1.0.0 baseline) are listed in the data model, including `Requires/Library` and `Rev`. [Source: architecture.md#5-data-model] [Source: architecture.md#adr-003]
- Keep the header plain C-compatible (`#define` only, no Qt types) so C plugins can include it. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** build check plus a CTest duplicate-name check plus a manual save round trip.
- **Key scenarios:** no duplicate macro; the app behaviour is unchanged.
- **Per-AC verification:** AC #1 → header review against the list; AC #2 → grep the two headers: their intersection is empty; AC #3 → `document_tokens.h` absent; build passes; AC #4 → the CTest check passes, and fails when a duplicate is injected locally; AC #5 → save an unchanged project and diff it with the original (only `MDate` may differ)
- **Fixtures / mocks:** any existing project folder.
- **Edge cases to cover:** macros with the same name but different values (must be caught).
