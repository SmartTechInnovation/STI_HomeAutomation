# 9.3: Upload conflict: Overwrite or Merge

**Story ID:** 9.3  
**Epic:** 9 — Project sync and merge  
**Slug:** overwrite-or-merge-flow  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to choose between overwriting and merging when the controller changed since my last upload**,  
so that **I never erase users' settings by accident**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. On `revConflict(rev)` (6.7) a dialog explains "The controller project changed since your last upload (rev N)" and offers **Merge** (default) and **Overwrite**.
2. **Overwrite** asks a second confirmation showing how many values will be lost (from a merge dry run), then uploads with `force: true`.
3. **Merge** downloads Base (`GetBase`) and Controller (`DownloadProject`), runs 9.2, applies the change set to the open project as **one undoable macro**, and shows the summary; the engineer then saves and uploads with the new `baseRev`.
4. If the controller changed again before the upload, the flow repeats on the new difference.

## Tasks / Subtasks

- [ ] Dialog (AC: #1)
- [ ] Overwrite path with dry-run count (AC: #2)
- [ ] Merge path: fetch, merge, apply macro, summary (AC: #3)
- [ ] Retry loop (AC: #4)
