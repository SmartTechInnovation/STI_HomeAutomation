# 5.3: Plugin build template, cross toolchains and `.stixpkg` packaging

**Story ID:** 5.3  
**Epic:** 5 — Plugin SDK and C ABI  
**Slug:** plugin-build-template  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **a block author**,  
I want **a ready CMake template that builds my plugin for every controller target and packs it**,  
so that **publishing a package is one command**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `sdk/template/` contains a minimal plugin project (CMake, `Descriptor.xml`, `manifest.xml`, `icon.svg`, `src/block.cpp`).
2. Toolchain files `sdk/cmake/toolchains/linux-aarch64.cmake`, `linux-armv7hf.cmake` and `linux-x86_64.cmake` build `libstix_<name>.so` with hidden visibility, exporting only `stix_plugin_entry`.
3. `sdk/tools/stixpkg.py pack <dir>` produces `<Name>-<Vers>.stixpkg` with the ADR-004 layout and fills the per-file SHA-256 in `manifest.xml`; `--sign <key>` adds `SIGNATURE`.
4. The produced package installs in STIx Config (4.4) and passes the signature check (4.5) when signed with a trusted key.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Package layout and naming; binaries per target `lib/linux-aarch64/`, `lib/linux-armv7hf/`, `lib/linux-x86_64/`. [Source: architecture.md#adr-004]
- Accepted cost: each binary must be built for every controller target; mitigation: SDK CMake template plus CI cross-builds. [Source: architecture.md#adr-004]
- Signing: Ed25519 `SIGNATURE` over the manifest + SHA-256 of every file. [Source: architecture.md#adr-008]
- Python 3 is acceptable for an author-side tool; it is not shipped in the editor or runtime. [Inference]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->

- **Approach:** a separate CI workflow (`sdk.yml`) that cross-builds the template and installs the package in a test.
- **Key scenarios:** 3 targets build; pack + sign; install.
- **Per-AC verification:** AC #1 → template builds natively; AC #2 → `nm -D` shows only stix_plugin_entry; AC #3 → unzip and compare the layout; AC #4 → install test in STIx Config tests
- **Fixtures / mocks:** a test signing key.
- **Edge cases to cover:** a missing cross compiler → clear error.
