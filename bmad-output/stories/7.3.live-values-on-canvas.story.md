# 7.3: Show live values on ports, signals, wires and blocks

**Story ID:** 7.3  
**Epic:** 7 — Live monitoring and force  
**Slug:** live-values-on-canvas  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to see the live value next to every port and signal, and on wires**,  
so that **I can follow the logic while it runs**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Each port and signal shows its live value (Bool as on/off colour, numbers formatted with the unit, strings truncated) while monitoring is on.
2. Wires carrying a true Bool, or a changing value, are highlighted.
3. Forced items show a distinct "forced" badge; faulted (quarantined) blocks show a fault marker.
4. With monitoring off, nothing is shown and no bindings remain active.

## Tasks / Subtasks

- [ ] Port and Signal value labels (AC: #1)
- [ ] Wire highlighting (AC: #2)
- [ ] Forced and fault badges (AC: #3)
- [ ] Disable cleanly (AC: #4)

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- `LiveValues` publishes per-frame updates to `Port.qml`, `Signal.qml`, `Block.qml` (fault marker) and the properties panel. [Source: architecture.md#component-livevalues-l3-new]
- Forced values are visibly flagged in the UI. [Source: architecture.md#adr-008]
- A quarantined instance shows a fault marker. [Source: architecture.md#adr-005]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. Never run tests or quote coverage here. -->
