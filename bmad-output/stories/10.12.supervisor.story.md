# 10.12: `stix-supervisor`: crash and hang detection, quarantine

**Story ID:** 10.12  
**Epic:** 10 — STIx Runtime MVP (separate repository `stix-runtime`)  
**Slug:** supervisor  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **the controller**,  
I want **a crashing or hanging block to be isolated automatically**,  
so that **one faulty plugin can't take the whole installation down**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `stix-supervisor` is a small separate process that starts the runtime as its child and shares one page of POSIX shared memory (`/dev/shm`).
2. Before each plugin call the runtime writes the current instance id and increments a call counter in its per-thread record (two RAM stores; no syscall, no clock read).
3. On child death (SIGSEGV, SIGBUS, SIGFPE, SIGABRT…) the supervisor reads which instance was running, adds it to the quarantine list, writes **one** fault record, restarts the runtime (which skips quarantined instances) and reports `Fault {iuuid, reason:"crash", lastLog}`.
4. A thread stuck in the same instance with the same counter for more than `MaxCallMs` (500) → kill + restart through the same path (`reason:"hang"`).
5. The last log lines live in a shared-RAM ring buffer and are saved with the fault record; `ListFaults` / `ClearFault` work; the quarantine survives restarts until cleared or a new upload. No flash write happens in normal operation.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Crash and hang detection with no storage writes: `stix-supervisor` starts the runtime as its child and shares one RAM page (`/dev/shm`); per-thread record with current instance id and call counter, two plain stores per plugin call; on crash read the record, quarantine, write one fault record, restart, report; hang: sample every 100 ms, `MaxCallMs` 500. [Source: architecture.md#adr-005]
- Quarantined instance: callbacks no longer called; outputs keep their last value flagged Fault; survives restarts until `ClearFault` or a new upload. [Source: architecture.md#adr-005]
- systemd starts `stix-supervisor`, which starts the runtime. [Source: architecture.md#10-deployment-architecture]
- No feature may add per-call writes to storage. [Source: architecture.md#adr-005]
