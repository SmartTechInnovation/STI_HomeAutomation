# 3.1: `cmdConnect` / `cmdDisconnect`: undoable wiring, several sources per input

**Story ID:** 3.1  
**Epic:** 3 — Wiring and validation in the editor  
**Slug:** connect-commands  
**Status:** ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As **an integrator**,  
I want **to connect an output, an input signal or a variable to a block input or an output signal, and to disconnect it again**,  
so that **I can build the program logic, including many-to-many connections**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `Project_class::cmdConnect(sourceIUuid, targetIUuid)` adds `<Source Ref="sourceIUuid"/>` under the target `Input` (or `SignalOutRef`) as one undo step. The source may be an `Output`, a `SignalInRef` or a `Variable`.
2. An input may hold **several** `Source` elements; connecting the same source to the same target twice is refused (no duplicate `Source`).
3. One source may feed any number of targets, including two inputs of the same block.
4. `cmdDisconnect(sourceIUuid, targetIUuid)` removes exactly that `Source` as one undo step; undo restores it at the same position.
5. Both are built only from the existing primitives (`InsertNodeCmd`, `RemoveNodeCmd`); no new primitive is added.
6. Invalid ids (unknown, wrong element kind, target is an `Output`) are refused with `ErrorCode_e::InvalidArgument` and one log entry.

## Dev Notes

<!-- LOCKED. Cited guidance. [Inference] marks judgement calls not stated in the planning docs. -->

- Only mutation path: a `QUndoCommand` built from the primitives; compound operations are `QUndoStack` macros; every new edit adds a `cmd*` method on `Project_class` and **no** new primitive. [Source: architecture.md#adr-002]
- Data model: `Input` has **0..N** `Source/@Ref` → an Output, SignalInRef or Variable `IUuid`; `SignalOutRef` has 1 `Source`; how several sources combine is decided by the block. [Source: architecture.md#5-data-model]
- Many-to-many cases: one output → several inputs; several sources → one input; one output → two inputs of the same block. [Source: architecture.md#adr-005]
- Subscriber order in the runtime follows the order of the `<Source>` elements, so append new sources at the end. [Source: architecture.md#adr-005]
- Every `Input` and `Output` already receives its own `IUuid` in `cmdPlaceBlock`, so `Ref` always targets the Output's `IUuid`. [Inference] (from project.cpp)
- Type compatibility is checked in story 3.4, not here. [Source: epics.md#epic-3]
